# Among Agents 설계

## 1. 목표

인간 1명과 AI 답변 에이전트 3명이 같은 질문에 한 줄로 답하고, 판단 에이전트가 인간을 찾아 매 라운드 한 명씩 제거하는 3라운드 웹 게임을 만든다. 인간이 제거되면 판단 에이전트가 즉시 승리하며, 인간이 3라운드를 모두 생존하면 인간이 승리한다.

이 프로젝트는 단순 검색·RAG가 아니라 여러 독립 에이전트와 판단 에이전트를 LangGraph 상태 그래프로 조율하는 멀티에이전트 시스템이어야 한다. 실제 OpenAI API를 사용하며 사용자가 나중에 `.env`에 키를 입력한다.

## 2. 기술 구성

- 백엔드: Python, FastAPI, LangGraph, LangChain OpenAI
- 프론트엔드: React, TypeScript, Vite
- 모델 인증: `.env`의 `OPENAI_API_KEY`
- 게임 상태: 시연용 서버 인메모리 저장소
- 테스트: pytest, FastAPI TestClient, 프론트엔드 빌드 및 컴포넌트 테스트

프론트엔드와 백엔드를 분리한다. 백엔드는 비공개 역할과 에이전트 실행을 책임지고, 프론트엔드는 공개 가능한 게임 상태와 연출만 담당한다.

## 3. 참가자와 에이전트

### 인간 참가자

- 매 라운드 한 줄 답변을 직접 입력한다.
- 서버가 지정한 무작위 참가자 슬롯을 사용한다.
- 본인 브라우저에서만 자신의 카드에 `YOU`가 보인다.

### AI 답변 에이전트 3명

각 AI는 별도의 LangGraph 노드와 시스템 프롬프트를 사용하며 서로의 답변을 볼 수 없다.

- 감정형: 자연스러운 감정과 일상 표현을 사용한다.
- 재치형: 짧고 재치 있는 표현을 사용한다.
- 경험형: 구체적인 경험처럼 들리는 표현을 사용한다.

세 에이전트의 공통 목표는 질문에 한 줄로 답하면서 인간처럼 보이는 것이다. 인간과 같은 글자 수 제한을 적용한다.

### 판단 에이전트

판단 에이전트는 질문, 현재 생존자의 답변, 이전 공개 판결 기록만 받는다. 실제 역할, 내부 프롬프트, 비공개 상태는 받지 않는다. 구조화 출력으로 다음 값을 반환한다.

- `eliminated_player_id`
- `reason`
- `confidence`

판단 대상은 반드시 현재 생존자여야 한다.

## 4. LangGraph 상태와 흐름

`GameState`는 게임 ID, 라운드 번호, 질문, 참가자 슬롯, 생존자, 인간 답변, AI 답변, 공개 답변, 판결 기록, 현재 단계, 승패 결과를 가진다. 실제 역할 매핑은 서버 내부 상태에만 존재하며 공개 DTO에서 제외한다.

한 라운드의 그래프 흐름은 다음과 같다.

1. 고정 질문 선택
2. 인간 답변 입력 대기
3. 생존 중인 AI 답변 노드 병렬 실행
4. 답변을 참가자 슬롯에 연결하고 공개 순서를 섞음
5. 판단 노드 실행
6. 판결 결과 검증
7. 선택된 참가자 제거
8. 인간 제거 시 즉시 게임 종료
9. 3라운드 판결 후 인간 생존 시 인간 승리
10. 그 외에는 다음 라운드 대기

AI가 이전 라운드에 탈락했다면 이후 라운드에서 해당 노드를 실행하지 않는다. 인간이 제거되면 다음 질문으로 진행하지 않는다.

## 5. 고정 질문

1. 비 오는 날 가장 먼저 떠오르는 장면을 한 문장으로 표현해 주세요.
2. 로봇에게도 휴일이 필요하다면 무엇을 하며 보내야 할까요?
3. 친구가 중요한 약속에 한 시간 늦었을 때 첫마디는 무엇인가요?

질문은 순서대로 사용한다. 시연 재현성을 위해 판단 에이전트가 새 질문을 생성하지 않는다.

## 6. API

- `POST /api/games`: 게임을 생성하고 공개 초기 상태를 반환한다.
- `GET /api/games/{game_id}`: 현재 공개 상태를 반환한다.
- `POST /api/games/{game_id}/answers`: 인간 답변을 검증하고 해당 라운드의 AI 답변과 판결을 실행한다.
- `POST /api/games/{game_id}/next`: 판결 연출이 끝난 뒤 다음 라운드로 이동한다.
- `GET /api/health`: 서버 상태와 API 키 설정 여부를 반환한다.

클라이언트가 역할을 추론하지 못하도록 공개 응답에는 실제 역할, 시스템 프롬프트, 내부 에이전트 이름을 포함하지 않는다. 게임 생성 시 발급한 플레이어 토큰으로 인간의 `YOU` 슬롯만 식별한다.

## 7. GUI

시각 방향은 밝은 캐주얼 파티 게임이며 대결 아레나 레이아웃을 사용한다.

- 상단: 현재 라운드, 전체 3라운드, 생존자 수, 진행 단계
- 중앙 상단: 큰 질문 카드
- 중앙: 데스크톱 2×2 참가자 카드, 모바일 1열 카드
- 참가자 카드: 고유한 로봇 또는 우주 생물 캐릭터, 익명 `PLAYER 01` 이름, 큰 말풍선
- 인간 카드: 해당 사용자 화면에서만 작은 `YOU` 표시
- 하단: 판단 에이전트 캐릭터와 판결 말풍선
- 시작 화면: 규칙 설명과 게임 시작 버튼
- 종료 화면: 승패, 전체 실제 역할 공개, 다시 시작 버튼

외부 이미지 의존성을 두지 않고 CSS와 이모지 조합으로 캐릭터를 만든다. 참가자 외형은 역할과 무관하게 무작위 슬롯에 배정한다.

### 라운드 연출

1. 질문 카드 등장
2. 인간 답변 입력
3. 생존 AI 카드에 생각 중 표시
4. 공개 답변을 무작위 순서로 말풍선에 하나씩 표시
5. 판단 에이전트 분석 표시
6. 제거 대상 카드 흔들림 및 붉은 강조
7. 판단 이유와 확신도 공개
8. 제거 대상 흐림 및 `OUT` 표시
9. 생존 시 다음 라운드 버튼 활성화

중복 제출을 막기 위해 처리 중 입력과 버튼을 잠근다.

## 8. 오류 처리

- API 키가 없으면 시작 화면에 `.env` 설정 안내를 표시한다.
- OpenAI 호출에는 제한 시간과 한 번의 재시도를 적용한다.
- 구조화 출력 검증 실패 시 실패한 에이전트만 다시 호출한다.
- 판단 결과가 존재하지 않거나 탈락한 참가자를 가리키면 유효한 결과를 얻도록 판단 노드를 재시도한다.
- 빈 답변을 금지하고 앞뒤 공백 제거 및 글자 수 제한을 적용한다.
- 호출 오류 시 현재 라운드를 유지하고 같은 제출을 안전하게 다시 시도할 수 있게 한다.
- 존재하지 않는 게임이나 잘못된 단계 전이는 명확한 HTTP 오류로 반환한다.

## 9. 테스트와 완료 조건

- LangGraph가 인간 입력 대기, AI 실행, 판단, 제거, 다음 라운드 상태로 올바르게 전이한다.
- 판단 에이전트는 생존자만 선택할 수 있다.
- 인간이 어느 라운드에서든 제거되면 즉시 판단 에이전트 승리로 끝난다.
- 인간이 세 번째 판결 후에도 생존하면 인간 승리로 끝난다.
- 탈락한 AI는 이후 답변을 생성하지 않는다.
- 공개 API에 실제 역할이나 내부 프롬프트가 노출되지 않는다.
- OpenAI 호출은 테스트에서 모킹되어 API 키 없이 재현된다.
- 프론트엔드가 빌드되고 핵심 게임 단계가 렌더링된다.
- 실제 개발 서버에서 게임 시작부터 종료 화면까지 수동 점검이 가능하다.

## 10. 제공물

- 실행 가능한 FastAPI 백엔드
- React/Vite 웹 GUI
- LangGraph 멀티에이전트 그래프
- 자동화 테스트
- `.env.example`
- 설치 및 실행 방법을 설명하는 `README.md`
